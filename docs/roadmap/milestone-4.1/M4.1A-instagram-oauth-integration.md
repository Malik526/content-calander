# M4.1A — Build Instagram OAuth integration

## Objective

Implement the credential-independent portion of Milestone 4.1 so Pickle Batch has a complete Instagram Login connection flow that can be verified with mocked Meta responses. Preserve the shared platform architecture and TikTok behavior while leaving live Meta validation for M4.1B and publishing for Milestone 4.2.

## Scope

- Implement Instagram authorization URL construction, authorization-code exchange, short-lived to long-lived token exchange, token normalization, identity lookup (`user_id` and `username`), and long-lived-token refresh in `publishing/instagram/`. Keep Meta request/response handling out of API routes.
- Treat malformed or unsuccessful Meta responses as structured integration errors without placing tokens, authorization codes, app secrets, response bodies, or signed credentials in exceptions or logs.
- Move provider-neutral Fernet serialization/encryption helpers out of `publishing/tiktok/credential_store.py` into an appropriately shared publishing module. Keep compatible TikTok re-exports and prove TikTok's hosted credential behavior is unchanged.
- Add Instagram hosted-credential save/load/access-token behavior using the shared `platform_credentials` table. Refresh only when permitted by Instagram's token-age/lifetime rules, serialize refresh through `credential_refresh_lock`, and use the existing compare-and-swap persistence contract after the lock is acquired.
- Add protected Instagram connect and disconnect routes plus the public callback route. Bind callbacks only through a single-use server-side OAuth state, persist `code_verifier=''`, exchange using the exact stored redirect URI, store only the long-lived token, and never return credential material.
- Add a nullable `oauth_states.return_target` to fresh SQLite schemas, existing SQLite migration handling, `ContentStoreProtocol`, `ContentStore`, `PostgresContentStore`, and a new sequential Postgres migration. Existing TikTok rows and calls must continue to work with a null target.
- Accept only exact return targets from a server-owned allowlist. Default web attempts to the configured Settings URL. Reject rather than store arbitrary URLs, protocol-relative URLs, lookalike hosts, or user-controlled redirect destinations. Append the Instagram callback outcome without discarding a permitted target's existing query parameters.
- Make OAuth-state consumption atomic and platform-scoped. A state created for TikTok must not be consumed or accepted by the Instagram callback, and an Instagram state must not be consumed or accepted by TikTok.
- Persist the current Instagram external account id when connecting or reconnecting, including when the user selects a different Instagram account. Never display the numeric id. Report the identity as `@username`; an identity-fetch failure must not fabricate a label or leak a token.
- Generalize the API access-log filter so `code` and `state` are redacted on both supported OAuth callback paths while unrelated request logging remains unchanged.
- Set Instagram's registry `connection_available=True`; the status endpoint must still report `connect_available=False` when Instagram server configuration is incomplete. Leave `publishing_available=False`.
- Add typed frontend API calls and a dedicated Instagram action hook. Every mutation must update or invalidate `queryKeys.platformConnection(userId, PlatformId.INSTAGRAM)` according to the Milestone 3.15 cache contract.
- Update Settings to start Instagram authorization, disconnect, display `@username`, process and remove the `instagram` callback query parameter, and show platform-specific progress and errors without coupling Instagram and TikTok action state.
- Add focused backend and frontend tests using mocked Meta HTTP behavior. Cover authorization URL parameters, no-PKCE state storage, owner binding, success, denial, absent/replayed/expired/wrong-platform state, malformed token responses, exchange failure, identity behavior, refresh timing and concurrency, reconnecting a different account, disconnect idempotency, incomplete configuration, cache updates, callback messages, isolation, redaction, and credential non-disclosure.

## Non-Goals

- Do not call the real Meta API, require Meta credentials, configure a developer dashboard, open a browser consent flow, deploy, or mutate production data.
- Do not implement Reels container creation, signed media delivery to Meta, `media_publish`, publishing limits, worker/reconciliation integration, platform-post materialization, or any Milestone 4.2+ behavior.
- Do not make the media bucket public or add Instagram-specific persistence tables or generic-table columns other than `oauth_states.return_target`.
- Do not move TikTok onto `return_target`; preserve its current Settings redirect except for platform-scoped state consumption and shared access-log protection.
- Do not persist or expose Instagram usernames in a new public identity table. Use the credential-backed identity seam defined by ADR-0018.
- Do not deploy the migration or application, add real secrets, or mark live Meta OAuth as verified.

## Acceptance Criteria

- Authenticated `POST /api/platforms/instagram/connect` returns a Meta authorization URL containing the configured client id, exact redirect URI, current Instagram scopes, response type, and a fresh state; it persists a short-lived, owner-bound Instagram OAuth state with an empty verifier and an allowlisted return target.
- `GET /api/platforms/instagram/callback` consumes the correct unexpired Instagram state once, performs mocked short- and long-lived exchanges, associates the connection with the authenticated state owner rather than callback input, stores only encrypted long-lived credentials, and redirects to the stored permitted target with a safe outcome code.
- Denied, missing, expired, replayed, wrong-platform, malformed-response, and failed-exchange callbacks produce safe outcomes without storing credentials, exposing provider details, or consuming another platform's state.
- A successful reconnect updates the connection to the newly selected Instagram account id; status never exposes that numeric id and shows `@username` only when the credential-backed identity lookup supplies it.
- Long-lived credentials refresh only within the documented refresh window, use the per-connection lock and CAS update, and are reused correctly when another caller refreshed first. Tokens and app secrets never appear in logs or errors.
- Disconnect deletes the caller's Instagram credential and marks only that caller's connection disconnected; repeated disconnects are harmless and other users and platforms are unchanged.
- `oauth_states.return_target` works for new and existing SQLite databases and Postgres migration `0011`; null legacy values remain valid. The persistence protocol and both implementations remain aligned.
- Uvicorn access-log filtering redacts `code` and `state` on both TikTok and Instagram callback paths, with regression coverage for unrelated routes and query parameters.
- Instagram reports connection availability only when both the implementation capability and valid server configuration are present, while publishing availability remains false and no Instagram `platform_posts` are materialized.
- Settings presents independent Instagram Connect/Disconnect/loading/error states, shows callback outcomes, removes processed callback parameters, updates the user-scoped Instagram query cache, and leaves TikTok behavior unchanged.
- The full controller validation suite passes without network access or inherited credentials.
