# M4.1B — Validate Instagram OAuth against Meta

## Objective

Validate the completed Milestone 4.1 connection flow against a real Meta developer app and professional Instagram tester account once the user's Meta security restriction is resolved. Capture durable, sanitized evidence without expanding into Reels publishing or production deployment.

## Context

Read these sources before validation:

- `AGENTS.md`
- `PROJECT_STATE.md`
- `docs/roadmap/milestone-4.1/M4.1A-instagram-oauth-integration.md`
- `docs/decisions/0018-instagram-integration-architecture.md`
- `docs/evaluations/productization/milestone-4.0-instagram-foundation.md`
- The Milestone 4.1 evaluation produced by M4.1A
- `src/content_automation/api/routes/platforms_instagram.py`
- `src/content_automation/publishing/instagram/`

## Scope

- Confirm the Meta app uses Instagram API with Instagram Login, the tester is a public professional Business or Creator account with the required app role, and the registered callback exactly matches `INSTAGRAM_REDIRECT_URI`.
- Accept app credentials only through approved local or hosted secret configuration. Never paste them into chat, commands captured as artifacts, fixtures, documentation, or tracked files.
- Run a real connect flow and verify the authorization request, public callback, short- to long-lived exchange, encrypted credential persistence, owner binding, ACTIVE status, and `@username` display.
- Disconnect and reconnect the tester account, verifying credential deletion/replacement and correct connection status after each step.
- If safely practical within Meta's timing rules, exercise the refresh seam; otherwise record refresh as automated-only and leave the limitation explicit rather than waiting or manipulating token timestamps in real storage.
- Inspect captured access logs and confirm callback `code` and `state` are redacted. Record only sanitized evidence.
- Re-run the automated validation relevant to any evidence-driven correction. Update the 4.1 evaluation, changelog, and project state with the live result and any remaining limitation.

## Non-Goals

- Do not create a Reel container, give Meta a signed media URL, call `media_publish`, test publishing limits, or perform any Milestone 4.2+ action.
- Do not deploy to production, merge, push, change billing, submit App Review, request Advanced Access, complete Business Verification, switch the Meta app to Live mode, or rotate secrets.
- Do not expose or persist raw access tokens, authorization codes, app secrets, OAuth states, numeric Instagram ids, or unredacted provider responses in run artifacts or repository documentation.
- Do not fabricate success if Meta account restrictions, dashboard access, callback reachability, or provider behavior blocks the flow.

## Acceptance Criteria

- The human-controlled tester account completes connect → callback → Settings status, and the UI displays the real `@username` without exposing the numeric Instagram account id.
- The stored connection belongs to the initiating Pickle Batch user, is ACTIVE only with an encrypted credential, and no other user's or platform's connection changes.
- Disconnect removes the credential and reports DISCONNECTED; reconnect restores a valid ACTIVE connection without retaining stale account identity.
- API responses, application output, access logs, screenshots, and written evidence contain no raw token, app secret, authorization code, OAuth state, or numeric external account id. Callback `code` and `state` appear redacted in captured access logs.
- The live-validation record states the environment, date, exact flows observed, failures or deviations, and which evidence was independently inspected versus reported by the human.
- Relevant automated tests remain passing after any authorized correction; unresolved Meta or infrastructure requirements are reported as blockers rather than bypassed.

## Validation

- Run the repository's automated backend and frontend validation after any code or documentation correction.
- Perform the interactive flow only after the Human Gate is satisfied, using an HTTPS callback endpoint containing the completed M4.1A code.
- Inspect sanitized connection records and logs without printing encrypted payloads or credential-bearing request/response bodies.
- No controller-owned browser gate is configured for this external OAuth flow; the human performs consent and validates the user-visible result.

## Documentation

- Add a new dated live-validation result to the Milestone 4.1 evaluation; do not rewrite the earlier automated-only result.
- Update `CHANGELOG.md` and `PROJECT_STATE.md` if the recorded implementation status or known limitations change.
- Add an ADR-0018 addendum only if real Meta behavior changes an architectural decision; operational observations belong in the evaluation.

## Human Gate

Before this item can execute, the human must regain Meta developer access, supply a correctly configured Business app and eligible tester account, register an exact HTTPS callback, configure credentials through approved secret storage, and perform interactive consent. The controller must stop before this YELLOW item; credentials, external account actions, and the browser authorization cannot be delegated to an autonomous agent.
