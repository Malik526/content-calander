# ADR-0003: Local Embedding Classification, Claude Kept as Reference

## Status

Accepted

## Context

Milestone 1's classification boundary (`ContentClassifier`) had exactly one implementation, `ClaudeClassifier`: every video's transcript went to the Anthropic API, so the default pipeline required a paid API key and a network round-trip per video just to decide which content pillar a video belongs to — a pure text-similarity decision among a handful of fixed categories, not a task that needs a frontier model. The question for this milestone was concrete: can a small, fully local, CPU-only semantic classifier route real transcripts accurately enough to automate scheduling, while failing safely (abstaining) on ambiguous or out-of-pillar content?

## Decision

- **`EmbeddingClassifier` becomes the default; `ClaudeClassifier` remains available as a reference/benchmark implementation**, selected via `config.CLASSIFIER` (`"embeddings"` default, `"claude"` optional) and constructed through a new `classification.build_classifier()` factory — `process_content.py` calls only that, never a concrete classifier class, so it stays classifier-agnostic. An unsupported value fails immediately and clearly (`Unsupported CLASSIFIER='foo'. Valid values: embeddings, claude`) rather than falling through to a default.
- **Local embeddings via `fastembed`, not `sentence-transformers`.** Both are mature, but `sentence-transformers` pulls in PyTorch (hundreds of MB to a few GB); `fastembed` (Qdrant) runs on ONNX Runtime with no torch and no CUDA dependency — a much better fit for "modest CPU/RAM usage" and "avoid heavyweight ML frameworks" on a tool that already added `faster-whisper`. Model: `BAAI/bge-small-en-v1.5` (fastembed's quantized ONNX build), 384-dim, ~65MB on disk, downloaded once to `config.EMBEDDING_CACHE_DIR` (`~/.cache/content-calendar/fastembed` by default — fastembed's own default is a `/tmp` path, which isn't durable across reboots, so this is pointed somewhere persistent instead). CPU-only; no GPU requirement. First embedding call after a cold cache takes several seconds (model load + download); every call after that is single-digit milliseconds.
- **Each pillar gets a semantic profile, not just its label.** `config.CONTENT_TYPES[key]` gained `classification_examples` (3-4 short reference examples per pillar, describing meaning rather than keywords) alongside the existing `label`/`description`. `label + description + examples` are joined into one text per pillar and embedded once (`classification._pillar_profile_text` + `EmbeddingClassifier._get_pillar_vectors`) — a single combined embedding per pillar, not an ensemble of per-example embeddings, kept deliberately simple for V1.2. Pillar vectors are cached on the classifier instance for the life of a `process_content.py` run (built lazily on first use, matching the existing lazy-load pattern of `FasterWhisperTranscriber`/`ClaudeClassifier`) — the model and pillar profiles are therefore loaded once per run, not once per video.
- **Cosine similarity is never reported as a probability.** `ClassificationResult` keeps its `confidence` field (to avoid a broader pipeline/schema refactor for a rename), but its meaning is now explicitly classifier-dependent — documented at the top of `classification.py` — and gained `classifier: str`, `second_score: float | None`, and `margin: float | None`. For `ClaudeClassifier`, `confidence` is the model's genuine self-reported confidence. For `EmbeddingClassifier`, it is the top pillar's raw cosine similarity — a real number that says "how aligned are these two vectors," not a calibrated probability. `process_content.py`'s CLI output and `_print_summary` label it "Similarity score" instead of "Confidence" for anything other than `classifier="claude"`.
- **Two gates, not one, for embeddings.** `EmbeddingClassifier` abstains (`pillar=None`) unless the top pillar's similarity clears `config.EMBEDDING_MIN_SIMILARITY` *and* its margin over the second-best pillar clears `config.EMBEDDING_MIN_MARGIN`. A single similarity threshold alone can't distinguish "clearly building" from "sits between building and acquisition" — the margin gate is what catches genuinely ambiguous content (both scoring similarly) and routes it to `NEEDS_REVIEW` instead of guessing. **Both thresholds ship as explicitly uncalibrated placeholder defaults** (`0.50` / `0.03`) — `config.py` says so directly in a comment. They are a starting point for `evaluate_classifier.py --sweep` to replace with evidence from real transcripts, not a claim that they're production-ready.
- **Every classifier owns its own auto-assign decision.** `ClaudeClassifier.classify()` now applies `AUTO_ASSIGN_THRESHOLD` internally and returns `pillar=None` when below it (this logic used to live in `process_content.py`). This is the change that makes the embeddings/Claude split architecturally clean: `process_content.py`'s gate collapses to `eligible = result.pillar is not None` — it never re-applies a confidence threshold, so it can't accidentally apply Claude's 0.80 confidence semantics to an embedding similarity score (which routinely sits well below that) or vice versa. `pillar=None` always means "abstain, route to `NEEDS_REVIEW`," full stop, regardless of which classifier produced it.
- **Abstaining beats guessing.** An empty transcript, an unrecognized pillar configuration, or a low-margin tie between two pillars all return a result rather than raising — `pillar=None` with a human-readable `reason`, never "pick the nearest pillar because something has to win." A classifier only raises `ClassificationError` (mapped to `videos.status=FAILED`) for a genuine failure: model load failure, an embedding call erroring, or invalid pillar configuration (missing `description`) — never for low confidence.
- **A local evaluation harness (`evaluate_classifier.py`) decides thresholds from evidence, not guesses.** It loads a labeled dataset (`labels.csv` + `transcripts/*.txt`), runs a chosen classifier over it, and reports total/auto-assigned/review counts, auto-assigned accuracy, **wrong auto-assignments** (the headline metric — content that would have been confidently scheduled into the wrong pillar), per-pillar accuracy, a confusion breakdown, and average latency. `--sweep` re-applies the two-gate policy (`classification._gate_decision`) to pre-computed scores across a similarity/margin grid, so trying more threshold combinations never re-embeds anything. It never imports `content_store` — there is no code path by which running an evaluation can mutate `videos`/`content_slots` or claim a slot.
- **Real transcripts, not synthetic ones, for calibration.** Transcription is deliberately factored out of evaluation (cache each real video's transcript once via `faster-whisper`, then benchmark every classifier against the identical cached text) so classifier quality is isolated from transcription quality. The dataset lives in a gitignored `evaluation/` directory (only `evaluation/README.md`, explaining the format, is committed) — personal creator transcripts never enter source control. A small synthetic fixture (`tests/fixtures/eval_sample/`) is committed instead, purely to exercise the harness's own logic in automated tests.

## Rationale

Embedding similarity search against a handful of short pillar descriptions is a well-understood, cheap, and — critically — inspectable technique: every decision reduces to "this transcript's vector was closest to that pillar's vector, by this margin," which is far easier to debug than an LLM's free-text reasoning, and costs nothing per video once the ~65MB model is cached. Keeping `ClaudeClassifier` alive as a second implementation behind the same interface means the two can be benchmarked against literally the same input directly, which is the only credible way to decide whether local embeddings are "good enough" instead of guessing.

## Consequences

- The default `process_content.py` pipeline requires **no Anthropic API key and no network call**: ffmpeg + faster-whisper + local embeddings + SQLite, entirely offline once the whisper and embedding models are cached.
- `videos` gained three nullable columns (`classification_second_score`, `classification_margin`, `classifier`) via a simple `ALTER TABLE ADD COLUMN` migration (`content_store._ensure_videos_columns`) — no rebuild needed, unlike the ADR-0002 `content_slots` constraint change.
- `EMBEDDING_MIN_SIMILARITY`/`EMBEDDING_MIN_MARGIN` are placeholders until someone actually runs `evaluate_classifier.py --sweep` against real labeled data from this account's own content. Treat the shipped defaults as "the pipeline runs," not "the thresholds are right."
- Comparing `confidence` values across classifiers is meaningless without checking `classifier` first — a downstream consumer of `videos.classification_confidence` (a report, a dashboard) must not average or threshold this column blindly.

## Guardrails

- Do not let `process_content.py` import `fastembed`, `anthropic`, or any concrete classifier class directly — only `classification.build_classifier()` and the `ContentClassifier`/`ClassificationResult` types.
- Do not treat `ClassificationResult.confidence` as a calibrated probability for `classifier="embeddings"` anywhere it's displayed or reported (CLI, evaluation harness, any future dashboard).
- Do not move the auto-assign decision back into `process_content.py`; each `ContentClassifier` implementation owns its own gating and must return `pillar=None` to abstain.
- Do not add a vector database, a hosted embedding API, or GPU/CUDA dependencies for this milestone's pillar count — a handful of cached in-memory vectors needs none of that.
- Do not commit real creator transcripts to `evaluation/`; only `evaluation/README.md` is tracked.
- A future `GemmaClassifier` (or any other `ContentClassifier`) must be benchmarkable through `evaluate_classifier.py --classifier <name>` without evaluator changes beyond adding the name to the CLI's `choices`.

## Current Implementation

- `classification.py` — `ContentClassifier`, `ClassificationResult` (with `classifier`/`second_score`/`margin`), `ClaudeClassifier` (now self-gating on `AUTO_ASSIGN_THRESHOLD`), `EmbeddingClassifier` (`score()` + `classify()`, lazy model/pillar-vector caching), `_gate_decision` (shared two-gate policy, reused by the evaluation sweep), `build_classifier()`.
- `config.py` — `CLASSIFIER`, `EMBEDDING_MODEL`, `EMBEDDING_CACHE_DIR`, `EMBEDDING_MIN_SIMILARITY`, `EMBEDDING_MIN_MARGIN`; `CONTENT_TYPES[*]["classification_examples"]`.
- `content_store.py` — `_ensure_videos_columns` migration.
- `process_content.py` — `classification.build_classifier()` at startup; `eligible = result.pillar is not None`; persists the three new classifier fields; CLI labels similarity vs. confidence correctly.
- `evaluate_classifier.py` — dataset loading, metrics, confusion reporting, threshold sweep.
- `evaluation/README.md` (format/instructions; real corpus gitignored), `tests/fixtures/eval_sample/` (synthetic, committed).
- `tests/test_embedding_classifier.py`, `tests/test_evaluate_classifier.py`, updated `tests/test_process_content_integration.py`.
